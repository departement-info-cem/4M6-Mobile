## Comment l'app parle à Léo2000

Rien n'est factice : chaque écran lit ou écrit ses données dans Léo2000 par **HTTP**. Vu aux séances [3](../cours/reseau-get), [4](../cours/reseau-post-dto) et [5](../cours/reseau-cookie).

1. **Retrofit** (dans `:commun`) : une interface Kotlin, une méthode par route (`@GET("api/groupes")`, `@POST("api/connexion")`…). Retrofit fabrique le code qui envoie la requête.
2. **DTO** : une `data class` Kotlin par objet JSON de l'API ci-dessous, champ pour champ. Gson transforme le JSON reçu en objets, et tes objets en JSON envoyé.
3. **Cookie de session** : la connexion (`POST /api/connexion`) renvoie `Set-Cookie: JSESSIONID=…`. Un `CookieJar` dans OkHttp le garde et le renvoie à chaque requête : c'est ce qui dit à Léo2000 **qui** tu es. La déconnexion le rend inutile.
4. **Asynchrone** : `enqueue` envoie la requête et rend la main tout de suite; la réponse arrive plus tard dans `onResponse` (le serveur a répondu, même 403) ou `onFailure` (pas de réponse). L'écran affiche une attente entre les deux et un message clair en cas d'erreur.

## L'API de Léo2000 pour le TP1

Préfixe `/api`, JSON UTF-8. Toutes les routes sauf `inscription` et `connexion` exigent le cookie de session, sinon **401**. Erreur : un code HTTP et le corps `{"message": "texte lisible"}`.

| Code | Sens |
|---|---|
| 400 | Données invalides (champ manquant, note hors 0-100, pondérations > 100 %) |
| 401 | Pas de session, ou mauvais courriel / mot de passe |
| 403 | Connecté, mais pas le droit (mauvais rôle, pas son groupe…) |
| 404 | Ressource inexistante |
| 409 | Conflit (courriel déjà pris, étudiant déjà inscrit) |

```text
UtilisateurDTO  { id: Long, nom: String, courriel: String, role: "ENSEIGNANT" | "ETUDIANT", matricule: String? }
GroupeDTO       { id: Long, cours: String, numero: String, session: String, enseignant: String }
EvaluationDTO   { id: Long, titre: String, ponderation: Double, date: String }      // date "yyyy-MM-dd"
NoteDTO         { id: Long, idEvaluation: Long, evaluation: String, ponderation: Double,
                  idEtudiant: Long, nomEtudiant: String, valeur: Double? }          // valeur null = pas saisie
ReleveDTO       { groupe: GroupeDTO, notes: [NoteDTO], moyenne: Double? }            // moyenne null = aucune note
```

| Verbe | Route | Corps envoyé | Réponse | Pour qui |
|---|---|---|---|---|
| POST | `/api/inscription` | `{courriel, motDePasse, nom, matricule}` | 201 `UtilisateurDTO` | public, crée un étudiant |
| POST | `/api/connexion` | `{courriel, motDePasse}` | 200 `UtilisateurDTO` + cookie | public |
| POST | `/api/deconnexion` | — | 204 | connecté |
| GET | `/api/moi` | — | 200 `UtilisateurDTO` | connecté |
| GET | `/api/groupes` | — | 200 `[GroupeDTO]` | enseignant : ses groupes · étudiant : ses inscriptions |
| POST | `/api/groupes` | `{cours, numero, session}` | 201 `GroupeDTO` | enseignant |
| GET | `/api/groupes/{id}/etudiants` | — | 200 `[UtilisateurDTO]` | enseignant du groupe |
| POST | `/api/groupes/{id}/etudiants` | `{matricule}` | 204 | enseignant du groupe |
| GET | `/api/etudiants?nom=…` | — | 200 `[UtilisateurDTO]` | enseignant |
| GET | `/api/groupes/{id}/evaluations` | — | 200 `[EvaluationDTO]` | enseignant du groupe, étudiant inscrit |
| POST | `/api/groupes/{id}/evaluations` | `{titre, ponderation, date}` | 201 `EvaluationDTO` | enseignant du groupe |
| GET | `/api/evaluations/{id}/notes` | — | 200 `[NoteDTO]` (un par inscrit) | enseignant du groupe |
| PUT | `/api/evaluations/{id}/notes/{idEtudiant}` | `{valeur}` | 200 `NoteDTO` | enseignant du groupe |
| GET | `/api/groupes/{id}/mes-notes` | — | 200 `ReleveDTO` | étudiant inscrit |

### Exemple : décrire l'appel « saisir une note »

L'enseignante Ada tape 78 pour Chloé dans l'évaluation Intra et appuie sur Enregistrer.

1. **Client, avant.** Dans `enseignant/…/EcranNotes.kt`, la lambda `onClick` du bouton met `enAttente = true` et appelle `service.saisirNote(idEvaluation = 4, idEtudiant = 3, NoteRequete(78.0))`, déclarée dans `commun/…/ServiceLeo2000.kt` avec `@PUT("api/evaluations/{id}/notes/{idEtudiant}")`. `enqueue` envoie la requête et la lambda se termine : l'écran reste utilisable et affiche l'attente.
2. **Requête.**
   ```http
   PUT /api/evaluations/4/notes/3 HTTP/1.1
   Content-Type: application/json; charset=UTF-8
   Cookie: JSESSIONID=8C1F…        ← ajouté par le CookieJar, reçu à la connexion d'Ada

   {"valeur":78.0}
   ```
3. **Serveur.** `ControleurEvaluations.saisir` reçoit `4`, `3` et le corps. `Session.exige()` lit le cookie et retrouve Ada : l'identité vient de la session, pas de la requête. `ServiceEvaluations` trouve l'évaluation, vérifie qu'Ada est enseignante, vérifie que 78 est entre 0 et 100 et que Chloé est inscrite, puis `DepotNotes.save`.
4. **Réponse.**
   ```http
   HTTP/1.1 200 OK
   Content-Type: application/json

   {"id":12,"idEvaluation":4,"evaluation":"Intra","ponderation":15.0,"idEtudiant":3,"nomEtudiant":"Chloé","valeur":78.0}
   ```
   Avec 120 : `400` et `{"message":"Une note vaut de 0 a 100"}`. Sans cookie : `401`.
5. **Client, après.** `onResponse` est appelé : `response.isSuccessful` est vrai, `enAttente = false`, la note de Chloé est remplacée dans l'état de la liste, l'écran se recompose et affiche 78. Avec un 400, on lit `errorBody()` et on affiche le message traduit. Avec `onFailure` (Léo2000 éteint), message « serveur injoignable ». Dans tous les cas, l'écran revient au repos : plus d'attente, bouton de nouveau actif.
