## L'API à ajouter

Mêmes conventions qu'au TP1 : préfixe `/api`, JSON UTF-8, cookie de session obligatoire (sinon **401**), erreur `{"message": "texte lisible"}`.

### Nouveaux codes

| Code | Sens |
|---|---|
| 409 | Une révision est déjà ouverte pour cette note, ou elle n'est pas dans le bon état |
| 503 | Omnivax (système légacy) ne répond pas, répond trop lentement ou refuse la clé |

### Nouveaux DTO

```text
RevisionDTO     { id: Long, idNote: Long, evaluation: String, nomEtudiant: String,
                  ancienneValeur: Double?, motif: String,
                  etat: "DEMANDEE" | "PROPOSEE" | "VALIDEE",
                  nouvelleValeur: Double?, justification: String?,
                  proposePar: String?, validePar: String? }
DeclarationDTO  { declarees: Int, dejaDeclarees: Int, erreurs: [String] }
NoteFinaleDTO   { matricule: String, nomEtudiant: String, noteFinale: Int?, dateDeclaration: String? }
                  // noteFinale null = pas encore déclarée; dateDeclaration telle que reçue d'Omnivax (jj/mm/aaaa)
```

### Révisions

Cycle : l'étudiant **demande** (`DEMANDEE`) → l'enseignant du groupe **propose** une nouvelle valeur (`PROPOSEE`; la même valeur = refus) → **un autre enseignant** valide (`VALIDEE`, la note change) ou rejette (retour à `DEMANDEE`).

| Verbe | Route | Corps envoyé | Réponse | Pour qui | Erreurs |
|---|---|---|---|---|---|
| POST | `/api/notes/{id}/revisions` | `{motif}` | 201 `RevisionDTO` | étudiant dont c'est la note, note saisie | 400, 403, 404, 409 |
| GET | `/api/revisions` | — | 200 `[RevisionDTO]` | étudiant : les siennes · enseignant : celles de ses groupes | |
| GET | `/api/revisions/a-valider` | — | 200 `[RevisionDTO]` | enseignant : `PROPOSEE` par un **autre** enseignant | 403 |
| POST | `/api/revisions/{id}/proposition` | `{nouvelleValeur, justification}` | 200 `RevisionDTO` | enseignant du groupe, état `DEMANDEE` | 400, 403, 404, 409 |
| POST | `/api/revisions/{id}/validation` | `{accepte}` | 200 `RevisionDTO` | enseignant **autre que** celui qui a proposé, état `PROPOSEE` | 403, 404, 409 |

### Notes finales (Omnivax)

| Verbe | Route | Corps envoyé | Réponse | Pour qui | Erreurs |
|---|---|---|---|---|---|
| POST | `/api/groupes/{id}/notes-finales` | — | 200 `DeclarationDTO` | enseignant du groupe | 403, 404, 503 |
| GET | `/api/groupes/{id}/notes-finales` | — | 200 `[NoteFinaleDTO]` (un par inscrit) | enseignant du groupe | 403, 404, 503 |

- **Déclarer** : pour chaque étudiant inscrit ayant une moyenne, Léo2000 envoie à Omnivax, en un seul appel, la moyenne **arrondie à l'entier**. Déclarer deux fois ne crée pas de doublon : le deuxième appel compte l'étudiant dans `dejaDeclarees`.
- **Consulter** : Léo2000 demande à Omnivax les notes finales du cours, pour la session du groupe et les matricules inscrits.
- La session du groupe (`H27`) devient pour Omnivax `annee: 2027` et `session: "H"`. Le format d'Omnivax est décrit dans son `LISEZMOI.md` ([séance 16](../cours/systeme-legacy)).
- L'URL et la clé d'Omnivax viennent de la configuration (`OMNIVAX_URL`, `OMNIVAX_CLE`), jamais du code.

## Défense à la main &#8203;<Highlight color="tip">6 points</Highlight>

<Etiquette type="main" /> Sans IA, 10 minutes :

- tracer au tableau une action choisie par le professeur, de l'appui sur le bouton à l'affichage, en nommant à chaque étape le fichier et la fonction (même forme que l'exemple du [TP1](tp1#exemple--décrire-lappel--saisir-une-note-)) :
  1. **client, avant** : le code qui s'exécute quand l'action est déclenchée (lambda, appel du service Retrofit);
  2. **requête** : méthode, URL, en-têtes (dont le cookie de session) et corps JSON;
  3. **serveur** : le code qui se déclenche (contrôleur, service, dépôt), d'où vient l'identité, et l'appel à Omnivax s'il y en a un;
  4. **réponse** : code HTTP, en-têtes et corps JSON, y compris pour un cas d'erreur (403, 409, 503);
  5. **client, après** : tout le code client parcouru depuis la réception de la réponse **jusqu'au retour au repos** (état modifié, recomposition, navigation ou message d'erreur);
- dire combien d'objets de chaque classe serveur existent après N requêtes;
- montrer, dans le code, où est vérifiée une règle de `ACCES.md` choisie par le professeur, et la modifier devant lui.

Un TP que tu ne peux pas expliquer voit sa note plafonnée à la note de défense.

Tu peux demander une **défense à blanc** au professeur aux séances de travail avant la remise.
:::
