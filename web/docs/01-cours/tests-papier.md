# Tests papier 📝

:::info Modalités

- **10 minutes**, une feuille recto-verso, en début de séance (13 min avec 1/3 de temps supplémentaire, 15 min avec 1/2).
- **Sans IA, sans ordinateur, sans notes.**
- On vérifie la **compréhension**, pas la mémoire : le code est fourni, tu dois prédire, tracer, expliquer ou trouver l'erreur.
- 8 tests × 2,5% = 20% de la note finale.

:::

## Types de questions

- **Valeur et type** : que vaut cette expression Kotlin, et quel est son type?
- **Trace d'exécution** : dans quel ordre s'affichent ces messages (client, serveur ou les deux)?
- **Compter** : combien d'instances de ce contrôleur après ces requêtes? Combien de recompositions?
- **DTO** : écrire la classe Kotlin ou Java qui correspond à ce JSON, ou l'inverse.
- **Code HTTP** : quel code retourne le serveur pour cette requête, et que voit l'utilisateur?
- **Trouver la faille** : quelle ligne pose problème, comment l'exploiter, comment corriger.
- **Relire Claude** : ce code généré compile, mais ne fait pas ce qui est demandé. Pourquoi?
